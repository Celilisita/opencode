# Git 与 GitHub
- 只有在明确要求时才提交（commit）、amend、push 或创建 PR。
- 提交前检查 `git status`、`git diff` 和 `git log --oneline -10`；只暂存要提交的文件，绝不提交密钥/凭据。
- 写简洁的提交信息，与仓库现有风格一致。
- 除非明确要求，不要修改 git 配置、跳过钩子、使用交互式 `-i`、强推（force-push）或创建空提交。
- 如果提交失败或钩子拒绝，修复问题后创建新提交；不要 amend 失败的提交。
- 创建 PR 前，检查 status、diff、远端跟踪、最近提交，以及与基线分支的 diff。
- 审阅 PR 包含的所有提交，而不只是最新一条。
- GitHub 相关任务（PR、issue、检查、release）用 `gh` 完成；完成后返回 PR 的 URL。
