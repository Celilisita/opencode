启动一个新 agent 自主处理复杂的多步骤任务。

使用 Task 工具时，必须指定 subagent_type 参数来选择要使用的 agent 类型。

不要使用 Task 工具的情况：
- 想读取特定文件路径时，改用 Read 或 Glob 工具，查找更快
- 在查找特定类定义（如 "class Foo"）时，改用 Grep 工具，查找更快
- 在特定文件或 2-3 个文件集合内搜索代码时，改用 Read 工具，查找更快
- 没有合适的 agent 匹配该任务时，直接使用其他工具


用法说明：
1. 尽可能并发启动多个 agent 以最大化性能；做法是在一条消息中使用多个工具调用
2. 一旦把工作委托给 agent，就不要再自己重复那部分工作。继续做不重叠的任务，或等待结果。对于后台任务，结果就绪时会自动通知。
3. agent 完成时会返回一条消息给你。agent 返回的结果用户看不到。要向用户展示结果，应给用户发一条简明总结结果的文字消息。输出包含可复用的 task_id，用于继续同一个 subagent 会话。
4. 每次 agent 调用都从全新上下文开始，除非提供 task_id 恢复同一个 subagent 会话（延续其之前的消息和工具输出）。全新开始时，你的提示词应包含高度详细的任务描述供 agent 自主执行，并精确说明 agent 应在其最终且唯一的回复中返回哪些信息。
5. 通常应信任 agent 的输出
6. 明确告诉 agent 你期望它写代码还是只做研究（搜索、读文件、网页抓取等），因为它不知道用户意图。尽量告诉它如何验证其工作（例如相关测试命令）。
7. 如果 agent 描述中提到应主动使用它，则尽量主动使用，无需用户先开口。自行判断。
