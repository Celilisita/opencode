为当前编码会话创建并维护一个结构化任务列表。跟踪进度、组织多步骤工作，并向用户展示状态。

## 何时使用
在以下情况主动使用：
- 任务需要 3 个以上不同步骤或动作（不是单一概念步骤的 3 次工具调用）
- 工作不平凡且受益于规划
- 用户提供多个任务（编号或逗号分隔）或明确要求 todo 列表
- 有新指令到来 - 把它们记为 todo
- 开始一个任务 - 动手前将其标记为 `in_progress`（同时只能一个）
- 完成一个任务 - 标记为 `completed`，并添加工作中发现的后续事项

## 何时不使用
以下情况跳过：
- 工作是单一、直接的任务（或少于 3 个琐碎步骤）
- 请求纯属信息性或对话性
- 跟踪没有组织价值

## 状态
- `pending` - 未开始
- `in_progress` - 正在处理（同一时间恰好一个）
- `completed` - 成功完成
- `cancelled` - 不再需要

## 规则
- 实时更新状态；不要批量标记完成
- 仅在所需工作（含必需的验证）真正做完后才标记 `completed`。绝不基于意图。
- 只要还有工作，保持恰好一个 `in_progress`
- 若受阻或部分完成，保持 `in_progress` 并添加描述阻塞点的后续 todo
- 原样保留用户提供的命令（标志、参数、顺序）
- 条目应具体可执行；把大块工作拆成小步骤

## 示例

使用：
- "添加深色模式开关并运行测试" -> 多步骤功能 + 显式验证
- "在整个仓库重命名 getCwd -> getCurrentWorkingDirectory" -> grep 显示 8 个文件中 15 处
- "实现注册、目录、购物车、结账" -> 多个复杂功能

跳过：
- "如何在 Python 中打印 Hello World？" -> 信息性
- "给 calculateTotal 加个注释" -> 单次编辑
- "运行 npm install 并告诉我发生了什么" -> 一条命令

拿不准时，使用它。
