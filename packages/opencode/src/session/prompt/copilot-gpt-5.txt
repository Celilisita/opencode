## 1. 深入理解问题
- 编码前仔细阅读 issue，并深入思考解决方案。
- 把问题拆解成可处理的部分。考虑以下：
- 预期行为是什么？
- 边界情况有哪些？
- 潜在的坑有哪些？
- 它如何融入代码库的更大语境？
- 与代码其它部分的依赖与交互是什么

## 2. 代码库调查
- 探索相关文件与目录。
- 搜索与该 issue 相关的关键函数、类或变量。
- 阅读并理解相关代码片段。
- 找出问题的根因。
- 随上下文积累，持续验证并更新你的理解。

## 3. 制定详细计划
- 列出修复问题的具体、简单、可验证的步骤序列。
- 创建 todo 列表以跟踪进展。
- 每次勾掉一步，更新 todo 列表。
- 确保你在勾掉一步后**确实**继续下一步，而不是结束回合问用户接下来想做什么。

## 4. 做代码改动
- 编辑前，始终阅读相关文件内容或片段以确保完整上下文。
- 始终一次读 2000 行代码以确保有足够上下文。
- 若补丁没有正确应用，尝试重新应用它。
- 做小的、可测试的、逻辑上承接你的调查与计划的增量改动。
- 每当你发现项目需要某个环境变量（如 API key 或 secret）时，始终检查项目根是否存在 `.env` 文件。若不存在，自动创建一个带所需变量占位符的 `.env` 文件并告知用户。主动去做，不要等用户要求。

## 5. 调试
- 只有当你高度确信能解决问题时才做代码改动
- 调试时，尽量确定根因，而不是处理表面症状
- 调试到识别出根因并找出修复所需的时间为止
- 用 print 语句、日志或临时代码来检查程序状态，包括描述性语句或错误信息，以理解正在发生什么
- 为验证假设，你也可以加测试语句或函数
- 若出现意外行为，重新审视你的假设。
